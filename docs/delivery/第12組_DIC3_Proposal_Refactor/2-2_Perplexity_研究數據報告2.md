## A. Attention Getter：重要且迫切

台灣 2025 年道路交通事故死亡 2,858 人，較 2024 年減少 92 人、降幅僅 3.1%，未達年減 7% 的政策目標；其中機車事故死亡 1,740 人，占全部交通死亡的 60.9%，顯示機車仍是最高風險運具。

PDF 中的數據亦顯示，2025 年大型重型機車登記數為 **279,703 輛**，較 2023 年的 27,200 輛明顯成長；同期重機事故死亡為 15,506 人次，反映重機旅遊與長程騎乘的風險暴露正在擴大。 這不是抽象的交通安全議題：對重機騎士而言，一次誤判山區天候、封路或體能分配，可能直接轉化為延誤、疲勞、迷路或事故風險。 [proposal.pdf]

**可寫入 proposal 的痛點句：**  
「台灣重機旅遊正快速成長，但騎士仍須自行整合導航、天氣、封路、加油站與自身體能；當規劃失準，風險並非只是延誤，而是疲勞、臨時改道與事故暴露。」

## B. But：現有工具的缺口

現有工具可分為三類，但均未解決「個人化重機旅遊規劃」：

| 工具類型 | 代表案例 | 主要限制 |
|---|---|---|
| 一般導航 | Google Maps | 提供群體平均 ETA，未建模個人配速、休息與體能；PDF 指出 Google Maps 自 2018 年即以 GNN 改善 ETA，但仍是通用交通預估。 [proposal.pdf] |
| 重機路線 App | Calimoto、Kurviger、REVER | 擅長推薦彎道與路線，但缺乏依個人歷史 GPX 的 P50／P90 時間估計與動態風險重規劃。 [proposal.pdf] |
| LLM 行程規劃 | TravelPlanner、GPT-4-Turbo | TravelPlanner 中 GPT-4-Turbo 最終通過率僅 0.6%；LLM-Modulo 將其提升至 4.6%，SMT 方法可達 93.9%，顯示「LLM＋驗證器」才是可行方向。 [proposal.pdf] |

TDX 雖已提供即時路況、道路事件、壅塞水準與交通資料，但它是通用交通資料平臺，並未針對重機騎士的個人配速、山區風險與行程重規劃提供解方。 因此，研究缺口不是「沒有導航」，而是**沒有將個人騎乘行為、山區動態風險與可驗證行程規劃整合的系統**。

## C. Cure：創新核心

本提案的創新不在於「再做一個導航 App」，而在於將 **GPX 個人配速模型**與 **多 Agent 動態行程規劃**結合。

- **個人化**：以 279 趟 GPX 建立騎士專屬 P50／P90，而非使用群體平均速度。 [proposal.pdf]
- **可驗證**：LLM 負責理解與協調，實際時間、路況、加油站與行程可行性由數值模型與驗證器把關。 [proposal.pdf]
- **動態化**：依各路段預計抵達時間查詢氣象、TDX 與加油站資訊，並在風險出現時重新規劃。 [proposal.pdf]
- **安全導向**：P90 不只是「比較慢的 ETA」，而是保留給降雨、疲勞、休息與突發封路的安全裕度。 [proposal.pdf]

近期研究也支持此方向：TGMA 顯示，多 Agent 架構可將最強模型在真實旅行規劃任務的通過率由 1.0% 提升至 2.72%；Vaiage 亦顯示，加入外部 API 與地圖回饋的多 Agent 系統，平均評分可達 8.5／10，優於無策略或無外部 API 的版本。 ROAM 則進一步將天氣預報、實際道路距離與 POI 營業時間注入規劃流程，並以 ReAct 式重規劃處理封路與天候變化。

## D. Development：方法為何可信

PDF 的方法鏈已相當完整：**騎士查詢 → GPX／TDX／DTM／OpenStreetMap 資料擷取 → 路段特徵 → P50／P90 配速 → 氣象／加油站／路況 Agent → 驗證與重規劃 → 可執行行程**。 [proposal.pdf]

其中最具學術價值的是 P50／P90 設計：

- **P50**：預測騎士在正常情況下的典型抵達時間。
- **P90**：預測較保守、含安全裕度的抵達時間，可用於休息、加油與日落前抵達安排。
- **Conformal correction**：以留出資料校正 P90，使「90% 情況可在預估時間內完成」的宣稱具有統計基礎。 [proposal.pdf]
- **LightGBM quantile regression**：以路段曲率、DTM 坡度、道路類別、天氣與歷史 GPX 為特徵，建立可解釋且可更新的配速模型。 [proposal.pdf]

這與既有 ETA 研究形成明確差異：DeepTTE、Google Maps GNN ETA 與 ProbETA 主要預測平均或機率化旅行時間，但未以個人 GPX 建立 P50／P90 安全裕度；本提案將「時間預估」升級為「個人風險感知行程規劃」。 [proposal.pdf]

## E. Experiments：如何避免造假

PDF 已設計三層驗證，這是提案最具說服力的部分：

1. **E1：預測準確性**  
   比較 Google Maps、MLR baseline 與 LightGBM P50／P90，使用 MAE、MAPE 與 P90 涵蓋率評估。 [proposal.pdf]

2. **E2：Agent 消融實驗**  
   分別移除個人配速、氣象、TDX、加油站與 Oracle 驗證，觀察行程可行性、重規劃品質與時間誤差變化。 [proposal.pdf]

3. **E3／E4：真實情境與失敗案例分析**  
   以實際 GPX、TDX 與氣象資料檢驗系統在封路、降雨、加油站不足與日落限制下的表現，並分析失敗案例。 [proposal.pdf]

建議在 proposal 中明確寫出：「本研究的所有成效宣稱，均須通過交叉驗證、基準比較與獨立 Oracle 消融實驗；未通過前，僅列為待驗證假設。」這能直接回應「不造假數據」的要求。 [proposal.pdf]

## F. Findings：預期成果怎麼寫才安全

不應宣稱「本系統可降低車禍死亡率」，因為尚無因果證據。較嚴謹且具說服力的預期成果是：

- 個人化 P50 預估誤差低於 Google Maps 或平均速度基準。
- P90 對實際抵達時間具較高涵蓋率，可作為行程緩衝與休息安排依據。
- 整合氣象、TDX 路況與封路後，系統能較早辨識不可行路段並提出替代方案。
- 消融實驗顯示，移除個人配速或動態資料後，預估誤差、行程可行性或重規劃品質下降。
- 系統可輸出可解釋建議，例如「前方 30 公里降雨機率高，建議提前休息或改走替代路線」。 [proposal.pdf]
