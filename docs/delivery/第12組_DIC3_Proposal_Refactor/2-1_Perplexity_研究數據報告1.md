以下可作為 proposal.pdf 第 4 頁 A–F 摘要的**可驗證證據補強**。核心論點是：台灣機車風險高、重機旅遊需求真實，但現有導航與 LLM 行程規劃無法處理「個人騎乘節奏＋山區動態風險」，因此多 Agent 系統具備明確研究與應用價值。

## A. Attention Getter

台灣 2025 年道路交通事故 30 日內死亡人數為 **2,858 人**，較 2024 年減少 92 人、降幅 3.1%，但仍未達年減 7% 的政策目標；交通部並指出機車與高齡者死亡人數偏高，且自摔、自撞及無照駕駛是主要挑戰。 [udn](https://udn.com/news/story/7266/9375833)

其中，**機車事故死亡 1,740 人，占全年交通事故死亡 2,858 人的 60.9%**，與摘要中的數字一致；這使「重機旅遊安全與行程可行性」不是一般旅遊規劃問題，而是高風險移動場景。 [storm](https://www.storm.mg/lifestyle/11177001)

台灣機車總登記數約 **1,465.6 萬輛**，交通部統計資料亦將「大型重型機車」獨立列為車輛類別，並細分為未滿 550cc 與 550cc 以上，顯示大型重機已是可明確界定、具規模的用路族群。 建議在正式 proposal 中，將「28 萬輛」改為引用交通部最新月份的「大型重型機車登記數」原始統計表，避免數字隨月份變動而失準。 [motc.gov](https://www.motc.gov.tw/ch/app/data/doc?detailNo=1446329030327406592&id=56&module=survey&serno=202511270000&type=s)

## B. But：現有工具不足

一般導航提供的是**群體平均或即時車流估計**，並未針對重機騎士的經驗、體能、休息需求、山區彎道節奏與天候風險做個人化預估。TDX 雖已提供即時路況、道路事件、壅塞水準、CCTV、ETag 旅行時間等資料，但這些是通用交通資料，並非重機旅遊的個人化配速與安全規劃解方。 [data.gov](https://data.gov.tw/en/datasets/161171)

山區旅遊的關鍵困難在於**動態性**：天候、封路、施工、道路事件與路況會在行程執行中改變。TDX 的即時路況資料每分鐘更新，高速公路局也提供即時與預告性封閉資訊，證明「靜態路線規劃」不足以支撐長程重機旅行。 [data.gov](https://data.gov.tw/en/datasets/161171)

LLM 直接規劃行程的能力也確實不足。TravelPlanner 基準中，GPT-4 在須同時滿足多項現實限制時，成功率僅 **0.6%**；後續研究亦指出，直接以 LLM 產生可執行行程的通過率僅 0.65%，顯示單一 LLM 難以可靠處理多限制、多工具、多步驟的旅行規劃。 [dl.acm](https://dl.acm.org/doi/10.5555/3692070.3694316)

## C. Cure：Moto Touring Copilot

「重機旅遊規劃顧問（Moto Touring Copilot）」的定位，應是**以 LLM 理解需求、以外部資料與最佳化模組保證可行性**的多 Agent 系統，而非讓 LLM 直接生成整份行程。

近期研究支持此架構方向：

| 研究／系統 | 對本提案的啟示 |
|---|---|
| TravelPlanner | 證明 LLM 單獨規劃複雜旅行時，難以滿足硬性限制；GPT-4 成功率僅 0.6%。 [dl.acm](https://dl.acm.org/doi/10.5555/3692070.3694316) |
| TGMA | 主題導向多 Agent 架構將最強模型通過率由 1.0% 提升至 2.72%，並顯示加入環境感知可提升天氣調適分數。 [aclanthology](https://aclanthology.org/2025.emnlp-main.752.pdf) |
| LLMAP | 將 LLM 用於理解指令，另以多步驟最佳化處理時間、營業時間與任務依賴，優於 LLM-as-Agent。 [aclanthology](https://aclanthology.org/2025.findings-emnlp.416.pdf) |
| Vaiage | 多 Agent 加上外部 API 與地圖回饋，可改善行程可行性；完整系統平均 8.5／10，優於無策略與無外部 API 版本。 [papers](https://papers.cool/arxiv/2505.10922) |
| ROAM | 將天氣預報、實際道路距離與 POI 營業時間注入規劃流程，並以 ReAct 式重規劃處理封路與天候變化。 [arxiv](https://arxiv.org/html/2611.09407v1) |

因此，Moto Touring Copilot 的「Cure」可改寫為：**以多 Agent 分工，將騎士意圖理解、GPX 軌跡配速、路況／氣象檢核、加油站與休息點安排、行程重規劃分離，並以可驗證的約束條件確保行程可執行。**

## D. Development：個人配速是核心創新

使用 **279 趟 GPX 軌跡**建立個人化 P50／P90 配速模型，是本提案最有辨識度的部分。GPX 軌跡可提供時間、位置、速度與路段細節；相關研究已顯示，GPS 軌跡經去噪、重採樣、地圖匹配與道路屬性整合後，可計算距離、速度與基礎設施使用情形，且地圖匹配誤差約 5.64%。 [dl.acm](https://dl.acm.org/doi/10.1145/3681779.3696838)

建議將方法明確拆成四層：

- **軌跡前處理**：去除 GPS 漂移、停等點、異常速度與重複路段。
- **路段特徵**：距離、海拔起伏、彎道密度、坡度、路寬、速限、路面與行政區。
- **個人配速模型**：以歷史 GPX 估計 P50（典型時間）與 P90（保守／安全裕度時間），而非僅輸出平均速度。
- **動態行程整合**：各路段預計抵達時間，作為查詢氣象、TDX 路況、封路事件與加油站營業資訊的時間錨點。

這種設計也呼應最新路線規劃 Agent 研究：MobilityBench 指出，現有 LLM 路線規劃 Agent 在「偏好限制路線規劃」上明顯較弱，且需要整合交通、天氣與個人偏好等工具；Trip+ 則將天候、封路、交通與疲勞列入行程重規劃與體驗評估。 [arxiv](https://arxiv.org/html/2602.22638v2)

## E. Experiments：避免被質疑「造假」

摘要已正確將成果標為「待驗證假設」，這是提案的優點。建議進一步將實驗設計寫成可審查的流程：

1. **資料切分**：以 279 趟 GPX 依路線、騎士或日期分組，進行交叉驗證，避免同一騎士或同一山線同時出現在訓練與測試集。
2. **基準比較**：比較本系統 P50／P90 預估、傳統平均速度模型、Google Maps ETA，以及實際完成時間。
3. **誤差指標**：使用 MAE、RMSE、MAPE，以及「P90 是否涵蓋實際抵達時間」的覆蓋率。
4. **消融實驗**：分別移除個人配速、氣象、TDX 路況、加油站／休息點與 Oracle 檢核，量化各模組貢獻。
5. **獨立 Oracle**：由未參與模型開發的人員，依實際路況、封路、天氣與騎乘日誌判斷行程是否可執行、是否需改道或延後。

這樣可避免只宣稱「系統較好」，而能回答：**個人配速究竟比 Google Maps 平均 ETA 準多少？P90 是否有效降低遲到與行程壓縮？哪些 Agent 移除後，可行性或安全裕度明顯下降？**

## F. Findings：安全的預期成果

不應預先宣稱系統「會降低車禍死亡率」，因為目前尚無本系統對事故率的因果證據。較嚴謹的預期成果應是：

- 相較 Google Maps 或平均速度基準，個人化 P50 預估誤差降低。
- P90 預估對實際抵達時間具較高涵蓋率，可作為行程緩衝與休息安排依據。
- 整合氣象、TDX 路況與封路後，系統能較早偵測不可行路段並提出替代或延後建議。
- 消融實驗顯示，移除個人配速或動態資料後，預估誤差、行程可行性或重規劃品質下降。
- 系統可產生可解釋的行程建議，例如「此段預計 14:20 抵達，前方 30 公里降雨機率高，建議提前休息或改走替代路線」。
